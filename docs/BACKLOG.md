# 待办 / 未实现（Backlog）

功能已冻结。这里的条目**不会自动实施**；只有"阻断灰度的安全缺陷、数据完整性问题、
严重性能回归"才会插队。每条都写了为什么当时没做，避免以后重复讨论。

优先级：**P0** = 上线前必须评估 / **P1** = 灰度后第一优先 / **P2** = 有价值但不急 / **P3** = 可能永不实施。

---

## P0 · 上线前建议先评估

### B1. 上游截断的静默修补（数据完整性）

- **现状**：上游中途断开 → 网关正常收尾 → 客户端看到"变短但没有错误"的回答。
- **依据**：`docs/KNOWN-LIMITS.md` §5；`TestForwardHoldbackReadErrorKeepsReceivedBytes`
- **为什么没做**：改错误传播会改变客户端重试语义（可能触发重复计费），需要单独设计；
  且属于旧行为，不在本轮范围。
- **可选方案**：
  - (a) SSE 补一个 `event: error` 帧（需要解析 SSE 帧，工作量大）
  - (b) 直接 `abortHandler()` 断流（简单，但客户端体验更差）
  - (c) 保持现状 + 只在事件/日志里记 `upstream_truncated`（最小改动，可观测但不改变行为）
- **建议**：先加 (c)，灰度期统计频率再决定是否要 (a)。

### B2. `/api/rules` 与 UI 无鉴权（安全）

- **现状**：只有 `/api/events` 有 token；规则接口能读正则可推断你在保护什么，能加 `reject` 规则造成 DoS。
- **依据**：`docs/KNOWN-LIMITS.md` §10
- **为什么没做**：会改变所有现有调用方（UI、脚本）的调用方式，属于产品决策，不是本轮范围。
- **建议**：要么复用一个 `-admin-token`（同一令牌保护所有 `/api/*`），要么在 README 里把
  "必须前置网关"写得更硬。**注意**：如果要做，UI 也要一起改（`app.js` 已支持附带 token，改动很小）。

## P1 · 灰度后优先

### B3. 可逆脱敏 / 代名还原（原始需求里的 P1）

- **目标**：`13812345678 → «PHONE_1»`（同一请求内稳定映射），响应里再还原成真值。
  好处：模型还能正常推理、多轮一致、**中转站永远看不到真值**。
- **为什么没做**：需要改 `Rule` 模型（`replacement` 从静态文本变成模板）、引入 per-request
  映射表、并且**必须**改写响应字节（等于放弃"原样透传"，要做 A3 语义级 SSE 处理）。
- **风险**：这是本仓库唯一会破坏"响应字节不变"特性的功能，必须单独一轮设计。

### B4. `-peek-bytes` 自适应

- **现状**：固定 1MB，决定"能阻断多大的非流式响应"，也是内存主因（2.6MB/请求）。
- **数据**：`docs/PERF-BASELINE.md`（1MB → 2.6MB/req；256KB → 0.9MB/req）
- **可选方案**：按 `Content-Length` 决定（已知且 < 阈值才整包窥探，否则只窥探首 chunk）；
  这样大响应 TTFB 不再被 1MB 拖住。
- **注意**：不要引入新的用户可见开关（现有 `-peek-bytes` 够用）。

### B5. 请求头清洗 / 指纹（原始需求里的 P3）

- **现状**：`x-stainless-*`、`User-Agent`、`OpenAI-Organization` 等原样转发给中转站。
- **依据**：`docs/KNOWN-LIMITS.md` §11
- **方案**：白名单或黑名单式清洗（黑名单更安全），可选地把 UA 归一化。
- **为什么没做**：会改变上游看到的信息，可能影响风控/路由，需要灰度验证。

## P2 · 有价值但不急

### B6. 网关持有上游 key（客户端只发占位符）

- 客户端配置 `Bearer PLACEHOLDER`，网关按上游配置替换成真 key。
- 价值：真 key 不落到客户端配置、客户端日志、中转站日志。
- 成本：需要 key 管理（环境变量/文件/多上游路由），明显超出"极简"边界。

### B7. 每规则命中计数 + dry-run 模式

- 现状：只有响应侧的诊断事件有计数（且需 `-audit`）。**请求侧规则命中数完全不可见**。
- 价值：新规则先 dry-run 一周（只计数不改写），再决定是否启用；也能发现"规则从没命中过"。
- 成本：需要在 `protector` 上加计数器 + 一个只读接口 + UI 展示；与 `-audit` 的定位要理清
  （建议：计数常开、内容相关的东西仍默认关）。

### B8. 响应 `usage` / `system_fingerprint` 合理性校验

- 现状：只核对 `model` 字段。
- 价值：中转站篡改用量、隐藏裁剪上下文的检测。
- 成本：需要维护"模型上下文长度/价格"表，属于外部知识，容易过期。

### B9. 检测器补充与降噪

- 缺 IPv6、更多云厂商前缀（Azure、Cloudflare、Vercel、Supabase…）。
- `email` / `ipv4` 在正常对话里噪声大，建议保持"默认关闭、按需开启"。
- 检测器目前无法配置"允许列表"（例如允许公司域名邮箱不被 mask）。

### B10. CI（当前仓库没有 `.github/workflows`）

- 建议最小配置：`go vet` + `go test ./...` + `go test -race ./...` + `gofmt -l` 检查。
- 注意：`TestConcurrentLargeResponses` 与几个 TTFB 断言在慢机器上可能波动，
  CI 上建议加 `-short` 跳过或放宽阈值（目前阈值已留 ~1.4–6× 余量）。

## P3 · 可能永不实施（记录原因）

| 想法 | 为什么不做 |
|---|---|
| 网关侧加密传输 | 中转站必须看明文才能调模型，加密没有意义 |
| TLS pinning 到上游 | 中转站自己终结 TLS，pin 不到 |
| 本地小模型做语义脱敏 | 违背"零依赖/极简"，且热路径延迟不可接受 |
| B2 升级成阻断 | 误报会随机打断正常回答，比泄漏更烦人 |
| 把 B1 改成模式匹配 | 同上；B1 的价值就在于"精确匹配 → 零误报" |
| 完整 SSE 语义级改写（A3） | 会破坏"响应字节原样透传"这个核心不变量；只有 B3 需要时才考虑 |
| 固定位数 / 熵形状规则取代 `.env` 已知值 | 用户已约定"敏感信息只放 `.env`"，已知值不需要猜；实测 `[A-Za-z0-9]{32}` 在本仓库 5698 行代码里误中 52 次 |
| `.env` 行结构检测器（`KEY=value` 形状） | 按已知值已覆盖；只有"密钥还没进 `.env`"时才需要，而那属于用户行为而非网关能力 |
| 请求侧出站巡检 + 每规则 dry-run 计数 | 已知值列表本身就是完整判据，巡检只会重复回答同一个问题 |
| 规则库静态加密 / 0600 / 行式明文格式 | 单用户本机场景下不是风险点；换来的只是运维复杂度（密钥必须与数据同机） |
| 命中已知值就返回 400 阻断 | 会打断 agent 工作流并触发重试循环；脱敏 + B1 回显拦截已足够 |
| 自动发现 `.env`（扫盘 / glob） | "扫到哪份"不可预测；路径列表由用户显式给出、启动日志逐份打印才是可核对的做法 |
